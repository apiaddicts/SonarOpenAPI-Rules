Los parámetros String deben tener restricciones de longitud mínima, longitud máxima, expresión regular o enumeración.

Ejemplo de código no compatible (OpenAPI 2)

    swagger: '2.0'
    info:
      version: 1.0.0
      title: Swagger Petstore
    paths:
      /items/{itemId}:
        get:
          summary: Obtener artículo por ID
          parameters:
            - name: itemId
              in: path
              description: ID del artículo
              required: true
              type: string
          responses:
            200:
              description: Detalles del artículo
              schema:
                type: object
                properties:
                  id:
                    type: integer
                  name:
                    type: string
            400:
              description: error

Solución compatible (OpenAPI 2)

    swagger: '2.0'
    info:
      version: 1.0.0
      title: Swagger Petstore
    paths:
      /items/{itemId}:
        get:
          summary: Obtener artículo por ID
          parameters:
            - name: itemId
              in: path
              description: ID del artículo
              required: true
              type: string
              minLength: 1
              maxLength: 10
          responses:
            200:
              description: Detalles del artículo
              schema:
                type: object
                properties:
                  id:
                    type: integer
                  name:
                    type: string
            400:
              description: error

Formatos exentos

Un parámetro de tipo string también cumple la regla cuando su format es uno cuyo espacio de valores ya queda acotado por el propio formato: date, date-time, uuid, ipv4 e ipv6.

La lista es fija y no distingue mayúsculas de minúsculas. No se ve afectada por la propiedad parameter_integrity: restringir esa lista, o vaciarla, no hace que un parámetro exento genere hallazgo. Los dos mecanismos se suman en lugar de sustituirse, así que añadir format a parameter_integrity hace que la mera presencia de cualquier formato satisfaga la regla, incluidos los formatos que no están en esta lista.

Cualquier otro formato sigue exigiendo una de las restricciones configuradas. Eso incluye email y hostname, que solo acotan el maximo sin fijar la forma del valor, ademas de password, uri, byte, binary y cualquier formato personalizado.

Solución compatible (formato exento)

  openapi: "3.0.0"
  info:
    version: 1.0.0
    title: My API
  paths:
    /items/{itemId}:
      get:
        parameters:
          - name: itemId
            in: path
            required: true
            schema:
              type: string
              format: uuid
        responses:
          200:
            description: Un item
